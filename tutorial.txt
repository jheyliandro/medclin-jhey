========================================================
  MEDCLINIC API — TUTORIAL DE EXECUÇÃO E TESTES
  Etapa 1: Autenticação e Autorização
========================================================

PRÉ-REQUISITOS
--------------
  - Node.js >= 18 instalado
  - npm >= 9 instalado
  - PostgreSQL >= 14 em execução (porta 5432)
  - Um cliente HTTP: Postman, Insomnia ou Thunder Client (VS Code)


========================================================
  PASSO 1 — CONFIGURAR O BANCO DE DADOS
========================================================

1.1 Crie o banco de dados no PostgreSQL.
    Abra o psql ou qualquer cliente (DBeaver, TablePlus, etc.) e execute:

      CREATE DATABASE medclin_db;

1.2 OU use o script seedb.js (recomendado para já criar a tabela e dados de teste):

      node seedb.js

    O script cria o banco, a tabela "users" e insere usuários fictícios automaticamente.
    Veja a seção PASSO 2 antes de rodar o seed.


========================================================
  PASSO 2 — CONFIGURAR VARIÁVEIS DE AMBIENTE
========================================================

2.1 O arquivo .env já foi gerado automaticamente.
    Abra o arquivo "projeto-bob-med/.env" e confirme/ajuste:

      PORT=3000
      DB_HOST=localhost
      DB_PORT=5432
      DB_USER=postgres          <- seu usuário do PostgreSQL
      DB_PASS=postgres          <- sua senha do PostgreSQL
      DB_NAME=medclin_db
      JWT_SECRET=sua_chave_secreta_aqui_troque_por_algo_forte
      JWT_EXPIRES_IN=1d

    IMPORTANTE: troque JWT_SECRET por qualquer string longa e aleatória.
    Exemplo: "medclinic_super_secret_2025_xK9!mP#qR"


========================================================
  PASSO 3 — INSTALAR DEPENDÊNCIAS
========================================================

    (Já feito se você recebeu o projeto com node_modules/.
     Caso contrário, execute dentro da pasta projeto-bob-med:)

      npm install


========================================================
  PASSO 4 — EXECUTAR O PROJETO
========================================================

4.1 Modo desenvolvimento (com hot-reload):

      npm run dev

4.2 Saída esperada no terminal:

      📦 Banco de dados conectado com sucesso.
      🚀 MedClinic API rodando em http://localhost:3000
         Prefixo base: /api

    A tabela "users" é criada automaticamente pelo TypeORM (synchronize: true).

4.3 Para parar o servidor: Ctrl + C


========================================================
  PASSO 5 — TESTAR OS ENDPOINTS
========================================================

URL BASE: http://localhost:3000/api

Todos os exemplos abaixo usam JSON no body e, onde indicado,
o header:  Authorization: Bearer <token>

--------------------------------------------------------
5.1  CADASTRAR USUÁRIO ADMINISTRADOR
--------------------------------------------------------

  Método:  POST
  URL:     http://localhost:3000/api/auth/register

  Body (JSON):
  {
    "name": "Ana Admin",
    "email": "ana@medclinic.com",
    "password": "admin123",
    "role": "admin"
  }

  Resposta esperada (201 Created):
  {
    "message": "Usuário criado com sucesso.",
    "user": {
      "id": "...",
      "name": "Ana Admin",
      "email": "ana@medclinic.com",
      "role": "admin",
      "createdAt": "..."
    }
  }

--------------------------------------------------------
5.2  CADASTRAR USUÁRIO ATENDENTE
--------------------------------------------------------

  Método:  POST
  URL:     http://localhost:3000/api/auth/register

  Body (JSON):
  {
    "name": "Carlos Atendente",
    "email": "carlos@medclinic.com",
    "password": "atendente123",
    "role": "attendant"
  }

  Resposta esperada (201 Created): igual ao exemplo acima,
  com "role": "attendant".

--------------------------------------------------------
5.3  TENTAR CADASTRAR COM E-MAIL DUPLICADO (erro esperado)
--------------------------------------------------------

  Repita o POST de 5.1 com o mesmo e-mail.

  Resposta esperada (409 Conflict):
  {
    "message": "E-mail já cadastrado."
  }

--------------------------------------------------------
5.4  LOGIN DO ADMINISTRADOR
--------------------------------------------------------

  Método:  POST
  URL:     http://localhost:3000/api/auth/login

  Body (JSON):
  {
    "email": "ana@medclinic.com",
    "password": "admin123"
  }

  Resposta esperada (200 OK):
  {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": { ... }
  }

  *** COPIE O VALOR DE "token" — será usado nos próximos passos ***

--------------------------------------------------------
5.5  LOGIN COM CREDENCIAIS INVÁLIDAS (erro esperado)
--------------------------------------------------------

  Método:  POST
  URL:     http://localhost:3000/api/auth/login

  Body (JSON):
  {
    "email": "ana@medclinic.com",
    "password": "senha_errada"
  }

  Resposta esperada (401 Unauthorized):
  {
    "message": "Credenciais inválidas."
  }

--------------------------------------------------------
5.6  VER DADOS DO USUÁRIO AUTENTICADO (rota protegida)
--------------------------------------------------------

  Método:  GET
  URL:     http://localhost:3000/api/users/me

  Header:
    Authorization: Bearer <token_copiado_no_passo_5.4>

  Resposta esperada (200 OK):
  {
    "user": {
      "id": "...",
      "name": "Ana Admin",
      "email": "ana@medclinic.com",
      "role": "admin",
      "createdAt": "..."
    }
  }

--------------------------------------------------------
5.7  ACESSAR ROTA SEM TOKEN (erro esperado)
--------------------------------------------------------

  Método:  GET
  URL:     http://localhost:3000/api/users/me
  (sem o header Authorization)

  Resposta esperada (401 Unauthorized):
  {
    "message": "Token de autenticação não fornecido."
  }

--------------------------------------------------------
5.8  TESTAR RBAC — ADMIN ACESSA /admin/ping
--------------------------------------------------------

  Método:  GET
  URL:     http://localhost:3000/api/admin/ping

  Header:
    Authorization: Bearer <token_do_ADMIN>

  Resposta esperada (200 OK):
  {
    "message": "pong",
    "role": "admin"
  }

--------------------------------------------------------
5.9  TESTAR RBAC — ATENDENTE TENTA ACESSAR /admin/ping (erro esperado)
--------------------------------------------------------

  Primeiro faça login com o atendente:

  POST http://localhost:3000/api/auth/login
  {
    "email": "carlos@medclinic.com",
    "password": "atendente123"
  }

  Copie o token do atendente. Depois:

  Método:  GET
  URL:     http://localhost:3000/api/admin/ping

  Header:
    Authorization: Bearer <token_do_ATENDENTE>

  Resposta esperada (403 Forbidden):
  {
    "message": "Acesso negado: permissão insuficiente."
  }


========================================================
  RESUMO DOS STATUS CODES
========================================================

  200  OK              → Requisição bem-sucedida (login, /me, /admin/ping)
  201  Created         → Usuário criado com sucesso
  400  Bad Request     → Campos obrigatórios ausentes ou e-mail inválido
  401  Unauthorized    → Credenciais inválidas ou token ausente/expirado/inválido
  403  Forbidden       → Usuário autenticado sem permissão para o recurso
  409  Conflict        → E-mail já cadastrado
  500  Internal Error  → Erro inesperado no servidor

========================================================
  ESTRUTURA DE PASTAS (RESUMO)
========================================================

  src/
  ├── controllers/   → recebe req/res, chama services
  ├── database/      → configuração do TypeORM (DataSource)
  ├── dtos/          → interfaces de entrada e saída
  ├── entities/      → entidade User (tabela "users")
  ├── middlewares/   → authenticate (JWT), authorize (RBAC), errorHandler
  ├── repositories/  → acesso ao banco via TypeORM
  ├── routes/        → definição dos endpoints
  ├── services/      → regras de negócio
  ├── utils/         → AppError, hash (bcrypt), jwt
  └── server.ts      → bootstrap da aplicação
